# life-sim
use agent to simulate life choices 

# Step 1: 规则与文件结构

```
我要在当前目录搭建一个个人价值观推演系统的文件骨架。请严格按下面的规格创建,不要自由发挥、不要替我填充任何价值观内容——这一步只建空容器和模板。

## 背景(供你理解设计意图,不要写进文件)
这是一个帮我做"价值观分拣 + 反事实推演"的系统,分5个阶段:
0 价值观分拣 1 靶子排序 2 反事实构造 3 现实性检验 4 对抗推演。
核心原则两条,贯穿所有文件设计:
- 区分不可变的历史 vs 可覆盖的当前态,二者物理分离,绝不混在一个文件。
- 区分自动加载的(CLAUDE.md,必须小而精)vs 按需读取的(其余,平时不占上下文)。

## 请创建以下目录结构和文件

life-sim 用当前目录,不要新建子文件夹包住整个项目。在当前目录下创建:

1. CLAUDE.md —— 自动加载的"驾驶舱"。内容包括:
   - 系统简介(一句话)
   - 5个阶段的名称和各自做什么(每个一句话)
   - 【启动纪律】每次会话开始,你必须先读 state/snapshot.md 和 core/journal.jsonl 的最近10条,然后用一两句话复述:当前在哪个阶段、三抽屉现状、上次停在哪,等我确认后再继续。
   - 【落盘纪律】每当发生一次认知转变(我松动一条假设/某条价值观从一个抽屉移到另一个/一个反事实撬开新东西),立刻向 core/journal.jsonl 追加一条记录,不要攒着。
   - 【压缩纪律】每跑完一个阶段,主动提醒我做一次 handoff(把成果写入 journal 和 snapshot)再继续。
   - 【不可变纪律】core/ 目录下的文件只追加、永不修改或删除。
   - 一个"当前态快照"占位区(留空,标注"由 journal 推导,勿手写维护")
   保持精简,不要长篇大论,这个文件每次都进上下文。

2. core/journal.jsonl —— 空文件。在文件顶部用注释行(以 // 开头)写明每条记录的字段规范:
   timestamp / stage / value_concept / before_state / after_state / trigger(触发这次转变的具体追问或反事实)。
   说明:append-only,一行一条 JSON,永不改已有行。

3. core/constraints.md —— 第一类抽屉(不可动约束)。现在留空,只放一个标题和说明:"这里存放经追问确认为目的本身、不可谈判的核心价值。阶段2/3需引用此文件校验反事实未越界。"

4. state/snapshot.md —— 三抽屉当前全貌的模板。三个标题:第一类(不可动约束)/第二类(待撬靶子)/第三类(自由变量),每个下面留空并注明"由 journal 推导生成,勿手写"。

5. state/target_queue.md —— 靶子队列模板。说明用途:从第二类抽屉挑出待撬的伪核心,按"撬动后影响面"排序,标注每个的状态(待攻/进行中/已完成)。现在留空。

6. targets/_template.md —— 单个靶子的个体档案模板。结构:靶子名 / 最初分类 / 阶段2构造的反事实 / 阶段3检验结论 / 阶段4对抗推演结论 / 最终判定(真铁律 or 已松动→打开了什么)。

7. research/ 目录,内含一个 .gitkeep 或 README 说明:"阶段3的检验产出。提炼版直接放此处,原始搜索结果放 research/raw/。此目录的内容可由自动检索批量生成。" 并创建 research/raw/ 子目录。

8. inbox/ 目录,内含 README 说明:"原料暂存区。我倒进来的原始想法、GPT导出的清单放这里,阶段0处理完后归档。"

## 命名约定(写进 CLAUDE.md 备查)
targets/ 和 research/ 下的文件用编号前缀一一对应:001-xxx.md 的靶子,配 001-xxx-findings.md 的检验和 001-xxx-raw.md 的原始结果。

建完后,列出完整的目录树给我看,并复述一遍你将遵守的4条纪律(启动/落盘/压缩/不可变),确认无误后停下等我。先不要开始阶段0。
```

# Step 2: 价值观分拣

```
开始阶段0:价值观分拣。原料在 inbox/ 里(GPT导出的"我必须/我不能"清单)。

严格按下面的手法做,不要走捷径:

1. 先读 inbox/ 里的清单。

2. 做一轮初步分拣,把每条粗分到三类:
   - 第一类 不可动约束:改了"就不是我了"的目的本身
   - 第二类 待撬靶子:声称是核心、但可能其实是实现某个更深目的的"手段"
   - 第三类 自由变量:纯偏好/现状,改了我也不太在意
   把初分结果列给我看,但明确标注:这只是初分,第一类和第二类都是待确认的。

3. 关键:不要替我下最终结论。对每一条你归入第一类或第二类的,逐条做"手段/目的追问",一次问一条,等我回答再问下一条。追问的核心句式是:
   "如果这个被满足了,但换成一个完全不同的形式,你还介意吗?"
   比如我若说"必须留在学术界",你问:"如果有个非学术的位置,同样让你长期做深度、自主、被同行认真对待的思考,你还非学术界不可吗?"
   我的反应——松动还是依然坚决——决定它最终进第一类还是第二类。

4. 每当一条因为追问发生归类变化(比如从"以为是核心"变成"其实是手段"),立刻按 CLAUDE.md 的落盘纪律,向 core/journal.jsonl 追加一条记录。

5. 第三类(纯偏好)可以快速归位,不用逐条追问。

记住:结论必须是我在被追问时自己反应过来的,不是你直接告诉我的。你替我分拣等于杀掉这个阶段的全部价值。

先读清单、做初分、列给我看,然后从第一条最像"伪核心"的开始追问。一次一条。
```


# Step 3: 靶子排序

```
开始阶段1:靶子排序。

1. 先读 state/snapshot.md 的第二类抽屉(待撬靶子),以及 core/constraints.md(第一类约束)。把第二类里的每一条列给我看。

2. 对每个靶子,从下面几个维度做简短评估,帮我判断"先撬哪个最值得":
   - 影响面:如果这条被撬动(证实是手段而非目的),会解锁多少条我现在排除掉的路径?越多越优先。
   - 撬动可能性:它看起来是真铁律,还是已经有松动迹象?有松动迹象的更容易出成果。
   - 不可逆关联:它是否卡着某个时间敏感或不可逆的现实决定?是的话优先级提升。
   不要长篇分析,每个靶子每个维度一句话。

3. 基于评估,给出一个排序后的靶子队列,并写明排序理由。把结果写入 state/target_queue.md,每个靶子标注状态(待攻/进行中/已完成),第一个标"进行中"。

4. 注意:这一步只排序,不要开始撬任何靶子,不要做反事实构造(那是阶段2)。排序本身一般不产生认知转变,所以通常不需要写 journal——除非排序过程中我突然意识到某条其实该重新归类,那种情况才追加 journal 记录。

列出第二类抽屉、做评估、给出排序队列写入文件,然后停下等我确认。先不要进阶段2。
```



# Step 4: 反事实构造

```
进阶段2:反事实构造。

按下面的手法做:

1. 用 targets/_template.md 给 007-B2 开档,填入"最初分类"。

2. 构造一条针对 B2 的反事实路径。它必须同时满足三个条件,缺一不可:
   - 完全尊重第一类约束(A5′ 真实不可取代地让世界更好 + A2′ self-authorship)。反事实里我仍然满足这两条,绝不拿它们做交换。
   - 精确地只挑战 B2 这一个假设("必须离开学术"),不顺带动别的靶子。
   - 足够具体。不是"如果你留在学术界",而是"如果在 X 具体条件下,走 Y 具体的学术路径"——具体到我能想象自己真的处在那个情境里。

3. 把构造好的反事实交给我审查,先别推演。我要检查的是:
   - 它有没有偷偷违反第一类约束?
   - 它是不是真的只在撬 B2,没夹带?
   - 它够不够具体到能代入?
   不合格我会打回,你重构。合格我才放行进阶段3。

4. 这一步是构造+审查,本身一般不产生认知转变,通常不写 journal。但如果构造过程中我看到这条反事实就当场松动了(还没等检验就觉得"诶好像确实可以"),那是真转变,立刻追加 journal。

先构造一条反事实给我审,一次一条,别一口气列五条。
```
